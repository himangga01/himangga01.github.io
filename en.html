Featured

01

Procurement Notice Reviewer

Problem
Reading notices and attached PDFs, then checking them against clients’ supporting documents, took 1–2 hours per notice.
Approach
I collected notices through public-data APIs, read scanned documents with PaddleOCR, retrieved references with RAG, and used Gemini to organize the requirements. I defined merge rules so an AI ‘Satisfied’ assessment becomes ‘Needs review’ without documentary evidence, and rule-based decisions take precedence when confidence is low.
Result
In practical use, review time fell to about 20 minutes per notice. I added 216 tests for the decision logic.
My role
  • Requirements and decision-rule design
  • Defining test criteria
  • Incorporating practical feedback

02

Two Office Websites

Problem
The office needed an online presence and a reliable way to receive consultation requests.
Approach
I built both sites using Node built-in modules without external packages and published them from one Mac mini through Cloudflare Tunnel. Consultation requests trigger email and Telegram notifications. Visitor statistics are anonymous and use no cookies.
Result
The office website has 56 pages in four languages. The school violence guidance site launched in August 2026. I diagnosed and fixed an external-access failure after a reboot and left a script to recover from the same issue.

  • Server and domain operations

03

Korean Text Polisher

Problem
AI-written Korean often retained translated phrasing and mechanical lists, making it difficult to use as-is.
Approach
I built a Windows app and skills that use Claude Code or Codex for polishing. A verification step restores the original sentence whenever numbers, quotations, or proper nouns change.
Result
Short-document processing dropped from 262 to 106 seconds. It missed the target of at most 40% of the original time by 0.5 percentage points, so I did not make it the default. I also used this tool to review the wording in this portfolio.
My role
  • Polishing rules and verification design
  • Performance measurement criteria
  • Distribution packaging

HOW I WORK

How I Work with AI

I built my personal projects with Claude Code and Codex as coding agents. I spent more time checking whether the results were trustworthy than simply getting code quickly.

  1. 1

    Agree on the design first

    I used GitHub Spec Kit to document requirements, designs, and task lists before handing off implementation.

  2. 2

    Tests first

    For each feature, I asked for a failing test first and recorded passing results in the work log.

  3. 3

    Independent AI review

    I assigned another agent to independently review the first agent’s work, incorporated the findings, and performed the final check myself.

What I handle

  • Requirements and priorities
  • Decision rules and verification criteria
  • Deciding which review findings to accept
  • Deployment, operations, and incident response

What I delegate to AI

  • Draft code and tests
  • Initial code reviews
  • Draft documentation

Unsupported judgments go to a person

  • Procurement: missing evidence means ‘Needs review’
  • Text polishing: changed facts revert to the original
  • Auction analysis: conflicting assessments require expert review
