02

사무소 웹사이트 2곳

문제
사무소를 알릴 곳과 상담 신청을 놓치지 않고 받을 방법이 필요했습니다.
접근
두 사이트 모두 외부 패키지 없이 Node 내장 모듈로 만들어 Mac mini 한 대에서 Cloudflare 터널로 공개했습니다. 상담 신청은 메일과 텔레그램으로 바로 전달되며 방문 통계는 쿠키 없이 익명으로 셉니다.
결과
4개 국어 56페이지의 사무소 홈페이지와 2026년 8월에 공개한 학교폭력 전문 사이트가 운영 중입니다. 재부팅 뒤 외부 접속이 끊긴 장애는 원인을 찾아 복구했고 같은 상황을 바로 되살리는 스크립트를 남겼습니다.
맡은 일
  • 구조 설계와 개인정보 처리 방식 결정
  • 서버·도메인 운영
  • 장애 대응

문제

접근
그래서 Claude Code나 Codex를 엔진으로 쓰는 윤문 도구를 Windows 앱과 스킬로 만들었고 윤문 뒤 검증 단계에서 숫자·인용·고유명사가 바뀐 문장은 원문으로 되돌리게 했습니다.

HOW I WORK

AI와 일하는 방식

개인 프로젝트는 Claude Code와 Codex를 코딩 에이전트로 두고 만들었습니다. 코드를 빨리 얻는 것보다 결과를 믿을 수 있는지 확인하는 데 시간을 더 썼습니다.

  1. 1

    설계를 먼저 확정

    GitHub Spec Kit으로 요구사항, 설계, 작업 목록을 문서로 정한 뒤 구현을 맡겼습니다.

  2. 2

    테스트를 먼저

    기능마다 실패하는 테스트를 먼저 쓰게 했고 통과 기록은 작업 로그에 남겼습니다.

  3. 3

    다른 AI가 교차 리뷰

    한 에이전트가 만든 결과는 다른 에이전트에게 독립 리뷰를 맡기고, 지적 사항을 반영한 뒤 제가 최종 확인했습니다.

제가 맡은 일

  • 요구사항 정리와 우선순위 결정
  • 판정 규칙과 검증 기준 설계
  • 리뷰 지적의 수용 여부 판단
  • 배포·운영과 장애 대응

AI에게 맡긴 일

  • 코드 초안과 테스트 코드 작성
  • 1차 코드 리뷰
  • 문서 초안

근거 없는 판단은 사람에게

  • 조달 공고: 근거가 없으면 검토 필요로 분류
  • 문장 다듬기: 사실이 바뀐 문장은 원문 복원
  • 경매 분석: 두 판단이 다르면 전문가 검토로 보류
